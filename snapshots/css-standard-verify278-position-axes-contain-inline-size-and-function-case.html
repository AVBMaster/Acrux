b278 — values read in the wrong place, and facts with no way to speak. A <position> names its axes by KEYWORD, not by the order the page wrote them, but 'object-position' took the first token as the horizontal axis: 'object-position: top' put 'top' on x and computed '0% 50%' where the reference engine says '50% 0%' — the image sat against the wrong edge. It now shares the parser the background and the mask already use, and 'background-position' echoes the pair the way 'mask-position' does. 'contain: inline-size' had no bit at all, so the one CSS Containment 3 keyword that is neither 'size' nor 'none' computed back as 'none' — and the first fix for it was itself wrong, because containment is per AXIS: measured, 'inline-size' collapses the inline size and leaves the block size to the contents, and does not make the box a containing block. The keyword list had no grammar either, so 'size inline-size', 'strict style' and 'none style' were stored as specified values that no sheet should have kept. The four 'contain-intrinsic' axis longhands had fields and no printer, so each computed the empty string; 'content-visibility' stored the draft's 'match-none'; and the 'container' shorthand said nothing at all. Last, the value fold lowercased every function name, which is right for 'RGB(' but wrong for the transform family: 'translateZ(10px)' came back as 'translatez(10px)', a name no CSS grammar has.
