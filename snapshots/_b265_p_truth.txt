The window was 1200x900 at 1 dppx? No — the reference window is the webview's own (used width
367px), so every C= that is a USED width is window-dependent and the comparator must skip it: rows
16, 17, 18 (refused width → used 367px), row 27 (calc(100% / 3) of that width) and rows 29-31 where
a percentage/absolute value resolves against it (recorded here so the ARITHMETIC can be read off the
specified echo instead).

What the reference answered:
* Substitution runs BEFORE the property is computed, and before a shorthand is expanded: s8
  ('--m: 4px 8px; margin: var(--m)') is '4px 8px 4px 8px' and s9 ('--t: 2s; transition: var(--t)
  ease') is a duration of 2s. A custom property must therefore be on the element's computed style
  before font-size, line-height or a shorthand reads it — s1 (20px), s2 (60px), s3 (18.6667px
  through a chain) and s4 (25px, declared AFTER the declaration that uses it) all say so.
* A var() nothing answers is IACVT, and IACVT is 'as if never written': the initial value for a
  non-inherited property (rows 0, 1, 6, 19, 20, 21, 22) and the INHERITED value for an inherited one
  (row 8 is black because nothing above it says otherwise; s5's child takes its parent's green).
* The three other ways to be unanswered are all IACVT the same way: an empty value ('--e: ;', rows
  2, 7, 17, and s6), a cycle ('--a: var(--b); --b: var(--a)' — rows 3, 11, 12), and a substitution
  that is no value of the property ('--x: 20px' given to opacity, row 5, and --sp: "12px" given to
  font-size, row 26 → the inherited 16px). A fallback, by contrast, answers: row 4
  ('var(--undef, 0.5)') is 0.5.
* A fallback that is never reached is not a problem: row 9 ('var(--red, var(--undef))' with --red
  defined) is green, while row 10 (the same the other way round) is green too because --red answers
  the fallback. Row 13 ('var(--a, var(--undef))' with --a a cycle) refuses.
* A custom property's own computed value reads back SUBSTITUTED (s3: --a is '14pt', the value of
  --b, not 'var(--b)'), and undefined or guaranteed-invalid ones read back as the empty string.
* Numbers are printed to six significant digits, ties to even: 14pt is 18.6562px (18.65625), the
  chain to 14pt is 18.6667px, 100px/7 is 14.2857px, 100%/3 is 33.3333% of the echo, and 1px*0.1 is
  0.09375px (exact, six digits and no more).
* 'border-width' computes 0px while 'border-style' is none (rows 19, 20, and every sheet row's
  blw=0px), and the length the page wrote the moment a style arrives (s10: 3px).
